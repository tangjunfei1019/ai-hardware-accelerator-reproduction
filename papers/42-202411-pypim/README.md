# PyPIM：从微架构设计到 Python 张量的数字存内处理集成

## 原文信息

- 原文标题：PyPIM: Integrating Digital Processing-in-Memory from Microarchitectural Design to Python Tensors
- 中文标题：PyPIM：从微架构设计到 Python 张量的数字存内处理集成
- 作者：Orian Leitersdorf、Ronny Ronen、Shahar Kvatinsky
- 年份与发表处：MICRO 2024（2024-11-02）
- arXiv / DOI：arXiv:2308.14007；DOI 10.1109/MICRO61859.2024.00119

## 核心方法

- 面向数字忆阻存内处理（PIM）的端到端集成：从高层 Python 张量库到底层微架构设计打通——微架构与指令集在底层控制外围与 PIM 并行抽象之间架桥；开发库把高层 Python 转成 ISA 指令；驱动把 ISA 指令翻译成 PIM 微操作。
- 微架构支持存储阵列内的并行位运算，并处理忆阻 PIM 特有的分区与沿阵列两个方向的操作。
- Python 库提供类似 NumPy / PyTorch 的张量操作，用户可以直接写张量程序，也能用已有算术函数拼出新的 PIM 例程；仓库分四部分：GPU 加速仿真器、微架构驱动、开发库与作为基准的测试脚本。
- 评估使用周期精确仿真器，在多类基准上验证 Python 库的通用性，并与理论 PIM 界比较性能。

## 核心效果

- 论文报告（以原文为准）：PyPIM 大幅简化 PIM 应用开发，让已有的面向张量的 Python 程序可以轻松转到 PIM；具体基准数字以原文表为准，本目录不把骨架的运算计数当作原文结果。
- 上游最小例子：`pip install -e .` 后运行 `python main.py`，预期输出 `32.0`。
- 峰值性能：未给出可比的峰值数字（相对理论 PIM 界的评估不是峰值）。

## 复现要点

- 复现目标：先跑上游仓库的最小例子，确认核心机制可工作；再跑论文配置，对照原文基线与方法描述。
- 要测量：正确性（张量运算结果与预期一致）、关键配置变化带来的趋势，而非只看单一加速比。
- 不会与原文一致的地方：工艺、器件参数、仿真器版本与基线配置差异都会改变绝对数字；骨架只演示思想。
